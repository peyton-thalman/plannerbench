The engine, in the chat

Ask in Claude or ChatGPT. The engine asks the questions and does the math.

In short

The same planning engine is a connector a person adds to Claude or ChatGPT in a couple of minutes. They ask in everyday words. The engine, not the chat model, decides which fact to ask for next, runs every plan, and hands back the answer with every assumption named and the law behind every dollar. The chat model’s job is to be friendly and quote the numbers exactly.

          Product rules

          Built into the tool, not hoped for in a prompt

          Every reply repeats these rules to the chat model, and the reply’s shape enforces most of them.

          • The engine picks the next question. It reruns the plan with each unknown fact both ways and asks only for the one that could flip the choice or move the answer more than 2%. Every question has a skip option that names the assumption it will use instead.
          • No made-up numbers. Every dollar amount comes from the engine. The model is told to quote, never compute, and a checker lists any number in a transcript that no tool reply contains.
          • Every fact is labeled. Said, assumed (with the reason), or worked out. Ballparks are labeled estimated, never “you said.”
          • Close calls get both plans. When two plans land within $1,000 over 25 years, it says “it’s close” instead of naming a winner.
          • Honest edges. A question the engine doesn’t cover gets “the engine doesn’t cover that yet,” not a guess.
          • It keeps nothing. No database, no files, no request bodies in logs. Anything that looks like a Social Security, account or ID number is refused and never repeated back.
          • Education, not advice. Said once per conversation. It prices choices; it never picks investments or products.

          How it’s checked

          Graded before anyone used it, then fixed from real use

          Simulated clients

          For each ask-first Gauntlet question, a scripted client answers only what the engine asks. Pass means the same decision as with every fact known, the number within 2%, a first answer within 6 questions, the hidden fact asked for, and no wasted questions. Free to run; no model is called.

          —

          Test drives become tests

          I ran it in Claude as a client would, with hard households (a widow with inherited IRAs, wages that run past 62) and wrote down every rough edge. Each note was fixed and that whole session was saved as a test, so it can’t slide back. One note changed a headline: the Social Security earnings test erased a “claim at 62” gain.

          —

          Engine tests

          Every rule, the everyday-words conversion, the ID-number refusal, a full round trip over the network, and the card drawn from real replies. The Gauntlet’s answer key is reproduced to the dollar from everyday words.

          For engineers

          The MCP server

          One server, two ways in: a local process for Claude Code and the benchmark runners, and a private web address for Claude and ChatGPT.

          • Tools. plan_check (the front door, in everyday terms) plus eight calculators for builders: —.
          • Replies are one of need_more (one question), answer, not_covered or rejected, each with a how_to_reply the model follows, and the engine commit that produced it.
          • Stateless over HTTP (Streamable HTTP, a fresh server per request): the conversation carries the facts, so there is nothing to store or leak. Requests capped at 64 KB, every list capped, a per-address rate limit.
          • A card inside the chat (MCP Apps): the answer, the conversion curve and what it costs vs. saves, drawn from the reply. One self-contained file with no outside requests. The text reply is always the whole answer, for clients that don’t draw cards (today that includes Claude’s phone apps).
          • The benchmark sees the same engine. PlannerBench runs the advanced tools over the local process, so a score on this site and an answer in the chat come from the same code.
