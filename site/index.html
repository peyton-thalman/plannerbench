Verified decision support for retirement planning

AI models slip when retirement rules stack up. A verified engine gets them right.

PlannerBench tests AI models on the math and the decisions financial planners face every week, against an exact answer key built from IRS, Social Security and Medicare rules. The planning engine that writes that key can also be handed to any model as tools it calls while it answers. This site shows what models miss, how the engine fixes it, and how every number is checked.

The story

Five steps, each one checked before the next

  1. Measure

    Ask models the questions planners actually compute: tax, Social Security, required distributions, Medicare premiums. Each has one exact answer under 2026 rules, so a script grades every reply.

    See the results →
    — → —Claude Sonnet 5.5 on one rule at a time, then on several rules meeting in one household

  2. Diagnose

    Most misses came from one misread rule: the senior deduction new in 2025. Models took its 6% phase-out once off a couple’s combined $12,000 instead of off each spouse’s $6,000. They agreed with each other, and the IRS form showed they were wrong.

    See the worked question →
    —models gave the same wrong answer

  3. Fix

    Hand the model the engine as tools. The first version returned the right number, and the model overruled it with its own wrong rule. Version 1.1 shows the rule and cites the IRS form line. The engine didn’t change; the explanation did.

    See the fix →
    — → —Claude Haiku 5.5 on the 50 hardest questions; — on held-out questions it never saw

  4. Prove

    A benchmark graded against a buggy key grades your bug. So the engine is checked by a second engine written by an agent that was never allowed to read the first, and by PolicyEngine-US, an open-source tax model built by others.

    See the method →
    —random households where the two engines agree on every field, to the dollar

  5. Stress-test

    Then the hard part: whole households and real choices (how much to convert to Roth, when to claim, how to give) where three or more rules stack across 25 years. Code proves no shortcut gets within 2% of the answer.

Who it’s for

The decision it changes

  • A wealth-tech team adding an AI assistant to its planning software. Today they guess what the assistant can safely answer. With PlannerBench they know: one-rule questions it handles alone; stacked ones (a Roth conversion, a claiming age, a widow’s taxes) go through the engine. The decision it changes is what the assistant is allowed to answer on its own.
  • Their compliance team. Every number the assistant shows comes from the engine, carries the rule and its IRS or SSA source, and was checked by programs that didn’t write it. That’s a review they can sign.
  • AI labs. Exact, current, hard-to-memorize questions in a field where a small error costs a family real money.

How it was built

A financial advisor, AI as the team, and a rule: build the judge first

Every piece here started with the check that would prove it right. That one habit drove most of the decisions.

01

Build the judge before the feature

Answer keys, graders and stand-in checks came before any model was asked a question.

02

The published source decides

When models agree against the key, the IRS form settles it, never the models.

03

Spend in capped steps

A smoke test under $1, then a small run under $5, then decide. The biggest run so far cost $5.39.
