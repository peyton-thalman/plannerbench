A benchmark for AI in financial planning

Can AI do a financial planner’s math?

PlannerBench asks AI models the questions advisors answer every week: taxes, Social Security, required distributions, Medicare premiums and compliance review. Each one has an exact answer under 2026 rules, so a script grades every reply.

    What the mistakes would cost a client

    Accuracy counts a Medicare premium ten cents off the same as a required distribution $9,000 too high. A planner wouldn’t. Here every answer is scored by how many dollars a year it is off from the key (monthly Social Security and Medicare answers times 12); a right answer is $0. A miss of $1,000 a year or more is called material: big enough that a client acting on it would notice. Only replies that gave a number count, so a model that often ran out of tokens is scored on fewer questions. Compliance questions have no dollar answer and are left out.

    Method

    Why you can trust the answer key

    A benchmark is only as good as its answers. If the key is wrong, you’re grading the model on your own bug. No question ships unless all of these checks pass, and ./reproduce.sh reruns every one of them.

    1. Published examples. Sixteen cases whose answers come straight from IRS, SSA and CMS tables must match exactly.
    2. Two independent programs. A planning engine and a separately written checker compute every answer. They agree on all — questions.
    3. Rules that must always hold. Thousands of random households test things like “more income never lowers tax” and “waiting a month never lowers a Social Security check.”
    4. Dataset health. No duplicates, and no task where one answer is common enough to guess.
    5. Human audit. Random cases come with worked solutions a CPA can check with a calculator.
    6. An outside tax model. PolicyEngine-US, an open-source tax model this project didn’t write, recomputes every tax answer. It agrees on all of them within $2, the new senior deduction included.
    7. Same model, two routes. Claude Haiku 5.5 was asked the same 140 questions directly and through OpenRouter. It scored 77% both ways, so routing doesn’t change scores.
    8. A held-out set. Private questions from a secret seed pass the same checks and are never published, so a model that trained on the public set still meets new ones.

    When models disagree with the key, the source decides, not the models. Models from several labs agreed with each other and against the key on the senior deduction; the IRS form, and separately PolicyEngine, showed the key was right. Several also answered Medicare premiums ten cents above the key; SSA’s 2026 table matches the key to the cent.

    Reading the results

    What they mean, and what they don’t

    • The math isn’t the problem. Models handle long-standing rules well. They slip on the newest ones, like the 2025 senior deduction, and on several rules interacting at once.
    • The fix is the rules, not a bigger model. Handing a model the current rule fixed most of its misses. AI built for advisors needs the rules supplied to it.
    • The compliance questions are a start. They define each issue in the question, and both models scored 100%. The next version names issues without defining them, which tests knowledge instead of reading.
    • It isn’t one lab’s blind spot. DeepSeek and GLM made the same senior-deduction misreading as Claude. gpt-oss-120b used the IRS life-expectancy table that was replaced in 2022 on every RMD it got wrong. Models know the rules as they were, not as they are.
    • Cheap can be good, but price per token misleads. DeepSeek V4.1 Flash tied Claude Haiku 5.5 overall and did better on the hardest questions. Haiku was still the cheapest per right answer. Models that think until they run out of room cost the most.
    • It’s still small. 10–15 questions per task per model, seven model setups so far. A gap of a few points is within the noise; the intervals show how much.
    • It measures math and rules, not advice. Judgment about what a client should do is out of scope for now.

    What’s next

    Toward a model that gets planning right

    1. Models from more labs, including low-cost ones, on the full set
    2. A CPA and a compliance professional sign off on the answer key
    3. Compliance questions that test what a model knows, not what it’s told
    4. The planning engine exposed as tools a model can call, scored against the model alone
    5. Reruns as new models ship, and new rules every January
