Demo walkthrough · private connector, not public

A private demo: the same calculator, inside Claude and ChatGPT.

What it is

This is a private demo; you can’t install it. The calculator from With a calculator also works as an add-on (a “connector”) for Claude and ChatGPT. Someone asks a retirement question in everyday words. The calculator, not the chat AI, decides which fact to ask for next, does the calculations, and says what it assumed. The chat AI is instructed to be friendly and quote the calculator’s numbers exactly.

Can I use it?

No. It runs at a private link while I test it, and there’s no public install. This page shows what it does, using its real replies to a made-up couple.

          How it behaves

          Most rules live in the calculator, not in a prompt

          • It picks the next question. It reruns the plan with each unknown fact both ways and asks only for the one that could change the choice or move the answer more than 2%. You can skip any question; it then says what it assumed instead.
          • Numbers come from the calculator. The chat AI is instructed to quote only the calculator’s numbers. In tests, a checker lists any number in a conversation that no calculator reply contains. That catches a slip; it can’t make one impossible.
          • Close calls get both plans. When two plans land within $1,000 over 25 years, it says “it’s close” instead of naming a winner.
          • It says what it doesn’t cover. A question outside its rules gets “that isn’t covered yet”, not a guess.
          • It keeps nothing. No database, no files, nothing you type in its logs. Anything that looks like a Social Security, account or ID number is refused and never repeated back.
          • Education, not advice. It prices choices; it never picks investments or products.

          How it’s checked

          Tested before anyone used it, then fixed from real use

          Simulated clients

          For each household question with a fact left out, a scripted client answers only what the calculator asks. A pass means the same decision as with every fact known, the number within 2%, an answer within 6 questions, the hidden fact asked for, and no wasted questions. No AI model is involved.

          —

          Test drives become tests

          I used it in Claude the way a client would, with hard households (a widow with inherited IRAs, someone still working past 62), and wrote down every rough edge. Each was fixed and the session saved as a test so it can’t come back. One changed a headline: the Social Security earnings limit erased a “claim at 62” gain.

          —

          Automated tests

          Every rule, the everyday-words input, the ID-number refusal, and a full round trip over the network. Given the same households in everyday words, it reproduces the household decisions’ answer key.

          For the technical reader: how it’s built
          • An MCP server (the Model Context Protocol, the standard way to plug tools into AI models). One server, two ways in: a local process for Claude Code and the benchmark runners, and a private web address for Claude and ChatGPT. The replies above are from engine commit —.
          • Tools. plan_check (the front door, in everyday terms) plus eight calculators for builders: —.
          • Replies are one of need_more (one question), answer, not_covered or rejected, each with a how_to_reply the chat model follows.
          • Stateless over HTTP (Streamable HTTP, a fresh server per request): the conversation carries the facts, so there is nothing to store or leak. Requests capped at 64 KB, every list capped, a per-address rate limit.
          • A card inside the chat (MCP Apps): the answer, the conversion curve and what it costs vs. saves. The text reply is always the whole answer, for apps that don’t draw cards.
          • The benchmark sees the same engine. PlannerBench calls the builder tools over the local process, so a score on this site and an answer in the chat come from the same code.
