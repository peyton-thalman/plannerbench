How I checked

Before grading the AI, I had to check my own answers

The plain answer

The planning engine (the program that works out the right answers) and a second, separately written program both compute every answer in the first test, and they must agree within —. Outside tax software built by other people recomputes the tax answers. Another engine, written by a separate AI agent that was never allowed to see the planning engine’s code, agrees within — on every one of — random households, and every question in the newer set must match it. Two human checks are still owed: a CPA’s sign-off and a person spot-checking the AI judge in the wrong-facts test.

That’s the whole idea. The rest of this page is the detail.

The answer key, in plain words

Every number question has one exact answer, usually a dollar amount. The planning engine, a program I directed AI agents to build, computes it from the 2026 rules: IRS forms and publications, the Social Security Administration’s operating manual, and Medicare’s premium tables.

For those number questions a script does the grading, so nobody’s opinion is involved, including mine. The wrong-facts test is the exception: whether a reply flagged a planted mistake takes judgment, so an AI judge decides, checked as described below.

When AI models disagree with the key, the published source decides, not the models. In the first test, models from several companies agreed with each other and against the key on the new senior deduction. The IRS form, and separately PolicyEngine, showed the key was right.

Where AI did the work, and what checked it

  • AI built it and graded it. The lead AI coding agent (Claude Code, working under my direction) wrote the planning engine, the questions, the grader and this site, and ran every test. I decided what to test, what counts as right, when to spend money and what to publish.
  • The engines above. A second engine written by a separate agent that never read the first, and outside tax software written by people, recompute the answers.
  • A second judge from another lab. In the wrong-facts test, an AI judge (Claude Haiku 5.5) reads each reply and records whether it flagged the problem. A judge from OpenAI (GPT-6 Luna) re-read — of those replies and agreed on —. Where a reply plainly named the problem but the judge marked it as missed, the lead AI agent corrected the label (— replies). Two AIs agreeing, or one AI correcting another, is not the same as a person checking.
  • The ChatGPT run. GPT-6 Luna’s replies were graded by the same answer keys and the same scripts as every other model. On wrong facts the same judge (Claude Haiku 5.5) used the same instructions, and the lead AI agent read every reply the judge marked as not catching the mistake (— replies; — labels changed). The replies the judge marked as caught haven’t been re-read yet. A first attempt was thrown out because most replies were a bare final number with no reasoning, which isn’t how ChatGPT answers a person; the details are on AI on its own.
  • An outside audit. On November 15, 2026, OpenAI’s GPT-6.1 Sol read the whole project, without changing anything, and looked for errors. It found —, all fixed on this version; the list is in the report.
  • Still owed. A CPA (a licensed tax accountant) hasn’t signed off on the answer key yet; worked solutions are ready for one to check with a calculator. That would be a human check on top of the independent programs, which already agree. And no person has yet spot-checked the AI judge’s labels in the wrong-facts test.

What every first-test question must pass

  1. Published examples. Cases whose answers come straight from IRS, Social Security and Medicare tables must match exactly.
  2. Two independent programs. The planning engine and a second, separately written program compute every answer and must agree within —. They agree on all — questions in the first test.
  3. Rules that must always hold. Thousands of random households test things like “more income never lowers tax” and “waiting a month never lowers a Social Security check.”
  4. Dataset health. No duplicates, and no task where one answer is common enough to guess.
  5. An outside tax model, where it reaches. PolicyEngine-US recomputes the first test’s tax answers and the 2026 federal returns in the whole-household decisions. It doesn’t cover required withdrawals, Social Security claiming or Medicare premiums.

The newer set’s questions must match the second engine before they’re used; its Arizona state-tax questions have no outside check. The human checks above are still open, so these are the automatic checks, not a sign-off.

For the technical reader: statistics, scripts and where each check lives
  • Every accuracy carries a 95% interval: the range the true score likely sits in. Small runs show wide ranges on purpose.
  • Comparisons are paired. “Alone vs. with the calculator” asks the same model the same questions and counts how many flipped each way, then uses McNemar’s test (a standard check of whether that many one-way flips could be luck).
  • Failures are their own bucket. A reply that ran out of tokens is published and counted as not right, never quietly dropped.
  • Mistakes are priced. Each wrong number in the first test is also scored in dollars a year off, so a ten-cent miss and a large one don’t count the same.
  • Hosts are pinned. Every outside model runs on one named host with data collection off; the private set never goes to free endpoints.
  • A held-back set. Held-back questions are private questions, made from a secret seed (a starting number for the generator), that pass the same checks and are never published, so a model that trained on the public set still meets new ones, and nothing is tuned on them.
  • What rebuilds the newer set. v2/grade.py regrades it from saved replies; v2/build_hard.py and v2/build_bad.py rebuild its questions and stop if the engine and an independent check disagree.
